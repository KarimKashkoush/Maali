# Classroom AI — الباك إند

Node.js يدير المدارس والمراحل والفصول والطلاب والصور والحضور، وPostgreSQL يحتفظ بالبيانات والعلاقات. خدمة Python مستقلة تعالج الصور وتعيد تطابق الوجه فقط. الفرونت يتصل بـ Node عبر مسار `/api/backend` داخل Next.js؛ مفاتيح قاعدة البيانات والتخزين والتعرف لا تصل إلى المتصفح.

## التشغيل المحلي

لإعادة تشغيل الإعداد الموجود على هذا الجهاز، نفّذ من PowerShell:

```powershell
& 'D:\AI\Maali\classroom_ai_backend\scripts\start-local.ps1'
```

يفتح الخدمات في الخلفية ويعرض رابط الدخول على 3100، مع حفظ سجلات التشغيل في `.local`. يتطلب build الفرونت الموجود بالفعل. `scripts/stop-local.ps1` يوقف فقط العمليات المسجلة بواسطة سكربت التشغيل ويترك PostgreSQL يعمل. الأوامر المنفصلة أدناه مفيدة للتطوير أو تشخيص الأخطاء.

المجلدات الثلاثة متجاورة تحت `D:\AI\Maali`: `classroom_ai_backend` و`classroom_ai_frontend` و`ClassroomAI`. استخدم Node.js 22.9 أو أحدث، وPython 3.11 مع مكتبات التعرف الموجودة في `.venv`. ملف `.env` المحلي مجهز ببيانات دخول عشوائية؛ لا تستبدله بـ `.env.example` على هذا الجهاز ولا تنشره.

1. PostgreSQL المحلي يعمل على `127.0.0.1:55432`. قاعدة التطبيق `classroom_ai` وقاعدة الاختبارات المنفصلة `classroom_ai_test`. بيانات العنقود داخل `C:\Users\karim\Documents\Codex\2026-09-22\hi\work\pgdata`. إذا كان متوقفًا بعد إعادة تشغيل الجهاز:

   ```powershell
   & 'C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe' -D 'C:\Users\karim\Documents\Codex\2026-09-22\hi\work\pgdata' status
   # نفّذ start فقط إن أظهر status أن الخادم متوقف.
   & 'C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe' -D 'C:\Users\karim\Documents\Codex\2026-09-22\hi\work\pgdata' -l 'C:\Users\karim\Documents\Codex\2026-09-22\hi\work\postgres.log' -o '-p 55432 -h 127.0.0.1' -w start
   ```

2. في نافذة طرفية داخل `D:\AI\Maali\ClassroomAI`:

   ```powershell
   .venv\Scripts\python.exe -m recognition_service.run --env-file ..\classroom_ai_backend\.env
   ```

3. في نافذة أخرى داخل `D:\AI\Maali\classroom_ai_backend`:

   ```powershell
   npm ci
   npm run migrate
   npm start
   ```

   Node يعمل على `http://127.0.0.1:4000`. التشغيل يطبق migrations الجديدة تلقائيًا أيضًا. استخدم قاعدة فارغة مخصصة عند التثبيت لأول مرة؛ لا توجهه إلى قاعدة المشروع القديمة. إعدادات تثبيت جهاز جديد موضحة في `.env.example`، ومنفذها الافتراضي 5432؛ عدّله إلى 55432 إن كنت تستخدم هذا العنقود.

4. داخل `D:\AI\Maali\classroom_ai_frontend`، تأكد أن متغير الخادم `CLASSROOM_API_URL=http://127.0.0.1:4000/api/v1`، ثم:

   ```powershell
   npm ci
   npm run dev -- --port 3100
   ```

   افتح `http://localhost:3100` وسجل الدخول بقيمتي `ADMIN_USERNAME` و`ADMIN_PASSWORD` من ملف الباك إند المحلي. استخدم نفس اسم المضيف أثناء الجلسة؛ لا تتنقل بين `localhost` و`127.0.0.1` حتى لا تفقد cookie الجلسة.

فحص الخدمات: `http://127.0.0.1:4000/health` يتحقق من Node وقاعدة البيانات، و`http://127.0.0.1:8001/health` يتحقق من Python. فحص Node لا يختبر Python أو التخزين؛ جرّب إضافة طالب بصورة صحيحة للتأكد من السلسلة كاملة. إذا كانت الخدمات تعمل بالفعل فلا تبدأ نسخًا إضافية على نفس المنافذ.

## الاستخدام وسلوك الحضور

- أنشئ مدرسة وحدد منطقتها الزمنية، ثم مرحلة مرتبطة بها، ثم فصلًا من المدرسة والمرحلة نفسيهما. اضبط وقت البداية، فترة السماح، مهلة الغياب، وقت الانتهاء وأيام الدراسة.
- إضافة الطالب تتطلب الفصل وصورة صالحة تحتوي على وجه واحد. يقبل JPEG وPNG وWebP حتى 5 MiB و16 مليون بكسل، ويحوّل Node الصورة إلى JPEG بعد تطبيق اتجاه EXIF وإزالة بيانات الملف الأصلية. يمكن حفظ حتى ست صور، ولا يمكن حذف آخر صورة للطالب النشط.
- قبل انتهاء مهلة الغياب تكون الحالة `pending`. الوصول حتى نهاية فترة السماح يسجل `present`؛ بعدها يسجل `late`. الطالب الذي لم يسجل وصولًا بعد المهلة يصبح `absent` عند قراءة/تحديث سجل اليوم. الأيام غير الدراسية تظهر `not_scheduled`. الغياب لا ينتج عن عدم ظهور الوجه في صورة واحدة.
- نافذة التسجيل تنتهي بوقت الانصراف. إذا وصل طالب بعد مهلة الغياب وقبل الانصراف يمكن تسجيله متأخرًا. تكرار التعرف لا يغير وقت الوصول الأول. الشاشة تسمح بتصحيح الحضور يدويًا، ويسجل الباك إند التعديلات في سجل المراجعة.
- اليوم يحتفظ بنسخة من الجدول والمنطقة الزمنية وأسماء الطلاب في سجلاته. تغييرات الجدول والمنطقة الزمنية تسري من اليوم التقويمي التالي حسب المدرسة، ولا تعيد حساب الماضي. نقل الطالب وإيقافه مرتبطان بتاريخ التسجيل للحفاظ على السجل.
- يتأكد Node من المطابقة في ثلاث إطارات متتالية قبل تسجيل الحضور الآلي. Python يقارن فقط بطلاب الفصل المرسلين له، ويرفض المطابقة الملتبسة. هذه الإطارات لا تمثل كشف حيوية: صورة وجه قد تشبه الوجه الحقيقي.

## حدود النسخة الحالية

حساب مدير واحد للنسخة التجريبية؛ لا توجد أدوار وصلاحيات متعددة أو فصل صلاحيات بين المدارس بعد. تسجيل الدخول إلزامي للوصول إلى البيانات والصور، والصور تُقرأ عبر API محمي. عند النشر يجب تفعيل HTTPS و`NODE_ENV=production` واستخدام Supabase Storage الخاص؛ التخزين المحلي للتجربة فقط.

لا يوجد استيراد تلقائي لبيانات النظام القديم، ولا تعديلات على قاعدته. دقة الوجوه تحتاج قياسًا على صور الطلاب والكاميرا الفعلية؛ النموذج الحالي أقل موثوقية مع الأطفال كما توضح [وثائق النموذج](https://github.com/ageitgey/face_recognition#caveats). احتفظ بالتصحيح اليدوي. التفاصيل التقنية في `../ClassroomAI/recognition_service/README.md`.

## الاختبارات

داخل الباك إند:

```powershell
npm test
```

تستخدم الاختبارات PostgreSQL حقيقيًا على `TEST_DATABASE_URL`، وترفض اسم قاعدة لا ينتهي بـ `_test`. قاعدة الاختبار مخصصة للاختبار فقط؛ لا تضع فيها بيانات مهمة. نتيجة التحقق الحالية: **22 اختبار Node و40 اختبار Python ناجحة**. عدّاد Node قابل للتغير مع إضافة اختبارات.

داخل `ClassroomAI`:

```powershell
.venv\Scripts\python.exe -m pytest recognition_service\test_service.py -q -p no:cacheprovider
```

اختبارات Python تشمل decoders وdlib الحقيقيين، لكن الوجوه الصناعية/الإطار الفارغ في اختبارات التشغيل لا تقيس دقة التعرف على الطلاب. اختبارات Node تستخدم بديلًا لخدمة التعرف لاختبار منطق النظام باستقلال عنها.

راجع `DEPLOYMENT.md` لإعداد Supabase والتخزين الخاص والنشر التجريبي والنسخ الاحتياطي. ملف `compose.yaml` يجمع الخدمات الأربع محليًا؛ واجهته على المنفذ 3000، بخلاف أمر التطوير 3100 أعلاه. Docker غير مثبت على جهاز التحقق الحالي، لذلك لم يُختبر بناء الحاويات هنا.
